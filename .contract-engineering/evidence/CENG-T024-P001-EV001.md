## Summary

Decomposed the 1094-line `scripts/validate-contract-records.py` into a
`scripts/contract_records/` package with 9 focused modules, each under
500 lines. The CLI file is now a 26-line thin entry point that re-exports
all public names from the package, so path-based test imports via

## Approach

- `constants.py`: all identifier patterns, state/domain sets, limits, and
  the identifiers module loader. The identifiers module is loaded from
  `scripts/identifiers.py` (one level up from the package).
- `loaders.py`: YAML loading with size/depth/node limits, JSON schema
  loading, resource limits, `fail()`, `ValidationResult`, `path_matches()`.
- `schemas.py`: JSON Schema validation for packets, epics, tasks, trackers.
- `security.py`: evidence policy validation and security semantic checks.
- `packet_rules.py`: acceptance contract, work metadata, open questions,
  planning records, owner validation, and the top-level `validate_packet()`.
- `tracker_rules.py`: tracker row parsing, consistency checking, and
  partition validation.
- `lock_rules.py`: protocol lock validation.
- `graph_rules.py`: dependency graph cycle detection, lock conflict
  detection, reference validation, and scope enforcement.
- `engine.py`: root resolution, record loading orchestration,
  `run_validation()`, `validate_canonical_tracker()` (which loads
  validate-tracker.py and render-tracker.py from scripts/), and `main()`.

`validate_canonical_tracker` uses `Path(__file__).resolve().parent.parent`
to find sibling scripts in `scripts/` from within `scripts/contract_records/`.
