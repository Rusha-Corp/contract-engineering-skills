# CENG-T023-P001-EV001

## Problem

v3.0.0 was published with an unsigned annotated tag (16f57f8) and no GitHub
Release. The stable release gate failed at `git verify-tag`. The protocol
fails closed on unsigned releases, so consumers could not adopt v3.

## Root cause

1. The tag was created with `git tag -a` instead of `git tag -s`.
2. `tag.gpgSign` was not set in git config.
3. The publisher GPG key (34049E9E) was not available on the release machine.
4. No local pre-push check existed to catch unsigned tags before publication.

## Remediation

### Key rotation
- Generated new ed25519 GPG key on the release machine.
- Fingerprint: 038022B4EDF5F704B38DF6C7BE1DF7FA3C3BC996
- UID: Emmanuel <kipronofb@outlook.com>
- Expires: 2028-11-04
- Old key retained in release-signing-key.asc for v2.7.2 and v2.8.0 verification.

### Pre-push signature guard
- Added scripts/verify_release_tag.py (extracted gate logic, 15 tests).
- Added .githooks/pre-push (blocks unsigned/mismatched stable release tags).
- CI workflow now calls verify_release_tag.py instead of inline Python.
- Documented in docs/release-integrity.md and CONTRIBUTING.md.

### Records CI fix
- CENG-T022-P001 had work_type: feature (not in schema enum).
- Corrected to work_type: delivery.
- Also fixed baseline_refs short SHA and missing handoff file.

### v3.0.0 marked incomplete
- v3.0.0 tag retained for audit trail.
- Consumers must not use v3.0.0 in locks.
- v3.0.1 is the first signed stable release of the record store seam.
