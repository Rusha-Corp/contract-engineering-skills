# CENG-T012-P001-EV002

## Result

Remote CI correctly rejected the first `v2.5.0` publication. The stable gate
reported that the attestation subject was not the direct parent of the tag.
The records job also rejected the completed packet because its packet YAML
still retained implementation locks even though the tracker row had released
them.

## Correction

- Do not rewrite the existing remote `v2.5.0` tag.
- Mark that tag unverified in the release record and supersede it with a
  corrective `v2.5.1` release.
- Release packet locks in packet YAML as well as the tracker projection.
- Use a clean two-commit release where the attestation-bearing tag is the
  direct child of the attested content commit.

## Validation

The failed CI run is retained as release-gate evidence. The corrective release
must pass the full Python 3.12 workflow and signed-tag stable gate before it is
treated as verified.
