# CENG-T012-P001-EV004

## Result

Remote CI correctly rejected the `v2.5.2` tag. The records job reported that
the protocol lock reference was not a valid 40-character commit SHA. The
attestation and lock both contained an extra trailing character in the
`e64048a` content commit reference.

## Correction

- Do not rewrite the existing remote `v2.5.2` tag.
- Preserve the failed run and mark `v2.5.2` unverified.
- Use the exact 40-character content SHA in the corrective `v2.5.3` lock and
  attestation.

## Validation

The failed CI run is retained as release-gate evidence. The corrective release
must pass the full Python 3.12 workflow and signed-tag stable gate before it
is treated as verified.
