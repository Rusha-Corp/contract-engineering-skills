# CENG-T025-P001-EV002

Post-handoff CI fix addendum (packet revision 1).

## Problem

After the v3.1.0 tag move (force-push), the `records` CI job crashed in the
"Enforce changed packet scope" step with `fatal: failed to stat` and exit
code 128.

## Root cause

On a tag push, `github.event.before` is the previous tag object SHA, which a
`fetch-depth: 2` checkout does not have, so `_base_reachable` returned False.
The unreachable-base fallback in `main()` then ran:

    git rev-list --max-parents=1 HEAD

which returns every commit in the fetched history as one multi-line string.
That string was passed to `git diff --name-only <base> <head>`, which git
rejects, crashing the script before the documented force-push skip rule in
`evaluate()` could run. The fallback diff was also dead code: `evaluate()`
returns immediately when `base_reachable` is False.

## Remediation

- `scripts/enforce_packet_scope.py`: the unreachable-base fallback no longer
  computes a diff at all (`changed = []`); `evaluate()` handles the skip.
- `scripts/enforce_packet_scope.py`: the unreachable-base rule is now checked
  before the no-records rule in `evaluate()`, so the skip message is accurate
  (an empty diff is "diff could not be computed", not "no records paths
  changed").
- `tests/test_enforce_packet_scope.py`: added a regression test that runs the
  CLI end-to-end with a bogus base SHA and asserts exit 0 plus the
  "unreachable" skip message.

- Full suite: 221/222 pass (1 pre-existing macOS tempdir symlink failure;
  passes on Linux CI)
- Manual regression: `enforce_packet_scope.py --base-sha <40 zeros>`

- Contract records validator, tracker validator, and render check: pass
