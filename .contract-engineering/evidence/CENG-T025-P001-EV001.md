# CENG-T025-P001-EV001

## Problem

The records CI job fails on dependency-only PRs (like dependabot PR #30),
evidence/handoff pushes, and force-pushes because the "Enforce changed
packet scope" step requires a work-packet file in every diff. Secret
scanning fails because the new GPG key fingerprint is not allowlisted.

## Root cause

1. The scope gate was inline Python in the workflow with no skip logic for
   diffs that touch no `.contract-engineering` paths.
2. The gate did not handle force-pushes where `github.event.before`
   references an unreachable commit.
3. The gate required a work-packet file for evidence/handoff-only pushes
   instead of claiming artifacts by filename pattern.
4. The new ed25519 GPG fingerprint (038022B4EDF5F704B38DF6C7BE1DF7FA3C3BC996)
   was not in the gitleaks allowlist.

## Remediation

### Scope gate extraction
- Created scripts/enforce_packet_scope.py (256 lines) with tested skip logic:
  - Skips diffs with no `.contract-engineering` paths
  - Claims artifacts by filename pattern when no work-packet is found
  - Skips unreachable base SHAs on force-push
- Added tests/test_enforce_packet_scope.py (249 lines, full coverage)
- Updated .github/workflows/protocol-validation.yml to call the script
- Updated tests/test_ci_validation.py for the new workflow structure

### Gitleaks allowlist
- Added both public GPG key fingerprints to .gitleaks.toml allowlist
  - 34049E9E (old RSA key for v2.7.2/v2.8.0)
  - 038022B4 (new ed25519 key for v3.0.1+)

### Documentation
- Documented packet-scope gate rules in docs/repository-development.md
