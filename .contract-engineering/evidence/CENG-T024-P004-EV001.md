# CENG-T024-P004-EV001

## Summary

Extended the protocol lock to support per-file hashing of skill folders via
`lock_version: 2`. This enables skills to be split into reference files
(needed by P005) while maintaining hash-verified integrity.
`lock_version: 1` remains fully supported for backward compatibility.

## What was built

### Validator: `scripts/contract_records/lock_rules.py`

`validate_project_lock` now accepts `lock_version` 1 or 2. For v2, when a
skill pin has a `files` map (`{file_path: sha256}`), each entry's hash is
validated against the SHA-256 pattern. v1 behavior is unchanged.

### CI workflow: `.github/workflows/protocol-validation.yml`

The "Verify lock and immutable source alignment" step now checks per-file
hashes when a `files` map is present. For each listed file, it verifies
both the locked ref content and the working-tree content match the expected
hash.

### Template: `templates/protocol-lock.yaml`

Added documentation comments explaining lock_version 1 vs 2 and the optional
`files` map.

### Docs: `docs/protocol-configuration.md`

Updated the lock file contract section to describe `lock_version` 1 or 2 and
the `skills.<name>.files` field. Updated the preflight script to verify
per-file hashes when a files map is present.
