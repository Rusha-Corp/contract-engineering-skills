# CENG-T026-P001-EV001

## Problem

Two release-machinery flaws surfaced during the v3.1.0 release:

1. The attestation's `verification.transparency_ref` is structurally
   pending forever. The hosted validation run is triggered by the tag the
   attestation is signed into, so the attestation can never cite its own
   run; editing it after publication would break the tag/subject parent
   relationship and force a re-tag with a new run it again cannot cite.
2. `protocol.lock.yaml` was pinned to a pre-rebase SHA inside a release
   packet commit; the PR #35 rebase stranded the pin and the records CI
   job failed with "protocol lock ref is not an ancestor of HEAD".

## Root cause

1. Chicken-and-egg design: transparency evidence was placed inside the
   signed attestation, where it is unreachable by construction.
2. The lock was finalized inside pre-merge content, on history that a
   rebase could rewrite.

## Remediation

### Attestation version 2 (transparency_ref dropped)
- `scripts/verify_release_tag.py` enforces version-aware rules: version 2
  forbids `verification.transparency_ref` and any `PENDING*` placeholder
  value anywhere; version 1 (v3.0.1, v3.1.0 at their tags) keeps verifying
  under the legacy rules.
- The main-branch attestation copy is bumped to `attestation_version: 2`
  without `transparency_ref`. The published v3.1.0 attestation at its tag
  stays version 1 (immutable) and still verifies.
- Transparency evidence convention: the public CI run for the tag push and
  the GitHub Release body; auditors bind it via the run's commit SHA.

### Scripted release finalization (lock drift fix)
- New `scripts/finalize_release.py`: given the content commit (default
  HEAD) it verifies the commit is an ancestor of HEAD, verifies every
  pinned skill hash (including lock v2 per-file hashes) against the
  content tree, rewrites `protocol.lock.yaml` `protocol.ref` and
  `development.ref` to the content commit, recomputes attestation
  artifact hashes from that tree, sets subject/provenance/builder_digest,
  writes version 2 without transparency_ref, rejects future timestamps
  and PENDING placeholders, and prints the follow-up commit/tag/verify
  commands. The lock and attestation changes land in ONE commit whose
  parent is the content commit — the only shape the stable gate and lock
  verifier both accept.
