## Scorecard limitation and fix

### Problem

OpenSSF Scorecard rejects non-default-branch refs with the message "Only the
default branch main is supported". The security workflow triggered on `v*`
tags from P020, causing the Scorecard job to fail on tag runs.

### Fix

The `scorecard` job now has an explicit `if: github.ref_type != 'tag'`
condition. Scorecard runs on `main` pushes, pull requests, scheduled runs, and
manual dispatch. It is skipped only for version-tag refs.

CodeQL and workflow-invariants jobs remain unconditional and still run on tag
refs, preserving tag-triggered release security coverage.

### Evidence

- `security.yml` scorecard job: `if: github.ref_type != 'tag'`
- `security.yml` codeql job: no `if` condition (unconditional)
- `security.yml` workflow-invariants job: no `if` condition (unconditional)
- All action refs remain pinned to 40-character SHAs.
- All workflows retain `permissions`, `timeout-minutes`, and
  `cancel-in-progress`.

The packet does not claim a skipped tag Scorecard run as a pass. Tag-triggered
security relies on CodeQL and workflow-invariant checks by design.
