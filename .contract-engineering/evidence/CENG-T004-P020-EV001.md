# CENG-T004-P020-EV001

## Issue identified

The stable release job in
`.github/workflows/protocol-validation.yml` was conditional on version-tag
refs, but the workflow trigger accepted only pushes to `main`. Consequently,
the stable-tag attestation gate could not run for `v2.2.1`. The published
`v2.2.1` tag remains unchanged; the branch workflows passed at commit
`ad45e4790cb381478e1847d44d16b6d7db462230`, but no tag-run gate existed.

## Implementation

- Protocol validation, Secret scanning, and Security checks now trigger on
  `main` and `v*` tag pushes.
- The stable gate reads `GITHUB_REF_NAME`, requires a version tag, and checks
  that the tag release name matches `release-attestation.yaml`.
- Active tracker maintenance is bounded to a 25-row index and 50-row
  task-shard limit.
- `scripts/validate-contract-records.py` loads all Markdown files under
  `tracker-shards/`, enforces task ownership, duplicate/orphan rejection, and
  the active index/shard limits while retaining archive partition checks.
- Guidance defines a 14-day active-packet review, terminal-only compaction,
  move-not-delete archive behavior, and recovery on failed moves.

## Local validation

- `python3 -m unittest discover -s tests -p 'test_*.py'`: pass.
- Workflow action refs and tag triggers: pass.

## Publication boundary

This packet does not rewrite or republish `v2.2.1`. The workflow fix requires
an independently reviewed future protocol release before consumers update
their lock. Existing terminal packets remain eligible for normal closure
rollover; this implementation does not archive them.
