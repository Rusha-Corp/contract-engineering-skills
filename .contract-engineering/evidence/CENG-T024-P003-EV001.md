# CENG-T024-P003-EV001

## Summary

Added a code-health gate to the contract record validator that enforces
file-size limits and dead-code review decisions. The recorded decision is
hard-gated (CI fails when missing); the outcome (whether to actually split
or remove) is left to the agent's judgment, checked by the reviewer at
handoff.

## What was built

### New module: `scripts/contract_records/code_health.py` (166 lines)

- `count_file_lines(path)` — returns line count for text files, None for binary
- `validate_size_reviews(packet, changed_paths, file_lines, max_file_lines, exclude)` —
  Rule 1: every changed text file over the limit needs a `size_reviews` entry
  with a valid decision (`decompose`, `retain` with rationale, `defer` with
  `follow_up_ref`)
- `validate_dead_code_review(packet)` — Rule 2: Handoff/Complete packets need
  `dead_code_review` with both `baseline` and `handoff` checkpoints, and every
  `dead_refs` entry needs a decision. `needs_evidence` blocks Complete.
- `validate_code_health(packet, changed_paths, file_lines, ...)` — runs both checks
- Constants: `DEFAULT_MAX_FILE_LINES = 500`, `DEFAULT_EXCLUDE = (".contract-engineering/",)`

### Engine integration

`_validate_code_health_for_packet` in engine.py reads `project.code_health`
config from the lock (max_file_lines, exclude), counts lines of changed files,
and calls `validate_code_health`. It runs after `enforce_scope` when
`--changed-path` is provided.

### Schema changes

`cleanup_scope` in `work-packet.schema.json` now has typed properties:
- `size_reviews`: array of `{path, lines, decision, rationale?, follow_up_ref?}`
- `dead_code_review`: array of checkpoint strings
- `dead_refs`: array of string (legacy) or `{ref, evidence, risk, decision, follow_up_ref?}`

### Template and docs

`templates/work-packet.yaml` updated with new `cleanup_scope` fields.
`docs/repository-development.md` has a new "Code-health gate" section.
