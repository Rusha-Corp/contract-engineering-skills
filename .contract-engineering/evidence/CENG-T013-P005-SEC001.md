# CENG-T013-P005-SEC001

## Threat Model: Gate Diagnostics and Adapter Conformance

### Scope

`scripts/gate_diagnostics.py`, adapter modules in `adapters/*/diagnostics.py`,
`tests/test_gate_diagnostics.py`, `docs/adapter-security.md`,
`docs/ci-security.md`.

### Actor boundary

The worker has repository-read, repository-write, and local-validation
capabilities only. No Factory hooks, remote systems, or external tools are
invoked.

### Trust boundaries

1. **TB-001**: Gate-failure inputs from validators and adapters enter the
   diagnostic envelope through `emit_diagnostic()` and `conform_adapter()`.
   Inputs are semi-trusted (caller-provided message strings).

2. **TB-002**: Adapter modules import from the canonical
   `scripts/gate_diagnostics.py`. They are thin re-export wrappers. Any
   modification to suppress diagnostics would be visible in review and fail
   the conformance test.

3. **TB-003**: The diagnostic module boundary is separate from the excluded
   Factory hook. No Factory hook capabilities are accessible.

### Threats and mitigations

**THR-001 (tampering, high risk)**: A caller could bypass fail-closed by
directly constructing a `DiagnosticEnvelope` with `blocking=False` for
security codes. **Mitigation**: `emit_diagnostic()` forces `blocking=True`
for `SECURITY_CODES` regardless of the `blocking` argument. The test
`test_security_cannot_be_downgraded_to_non_blocking` verifies this.

**THR-002 (tampering, medium risk)**: An adapter module could be modified to
suppress or downgrade security diagnostics. **Mitigation**: Adapter modules
are thin wrappers that re-export from the canonical module. The conformance
test (`test_adapter_preserves_security_blocking`,
`test_adapter_does_not_hide_gate_failure`) verifies all adapters preserve
blocking status. Any modification would be visible in code review.

**THR-003 (information-disclosure, low risk)**: Diagnostic messages could
leak sensitive information. **Mitigation**: Messages are caller-provided
strings; the diagnostic module does not read packet contents. The protocol
already requires redaction of sensitive data in governed records.

### AI agent risks

- **Prompt injection**: Repository content is treated as data; diagnostic
  messages cannot rewrite packet scope, approvals, or blocking flags.
- **Tool poisoning**: No external tool, MCP server, or Factory hook is added.
- **Excessive agency**: No network, remote-system, credential, or
  out-of-scope write capability is granted.
- **Secret exposure**: The diagnostic module handles gate-failure metadata
  only; no secrets are requested, emitted, or stored.

### Disposition

Pass. Zero critical, high, moderate, or low findings. All mitigations
verified by tests and evidence.
